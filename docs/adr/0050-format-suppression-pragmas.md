# Honor ruff's own `# fmt: off`/`# fmt: skip` pragmas as a suppression mechanism

## Context

`ruff format`'s own documentation (`docs/formatter.md`, "Format suppression") defines four pragma comments it honors: `# fmt: off` / `# fmt: on` (a statement-level block toggle), `# fmt: skip` (suppresses a case header, decorator, function/class definition, or the preceding statements on the same logical line), and YAPF's `# yapf: disable` / `# yapf: enable`, treated as equivalent to `# fmt: off`/`# fmt: on`.

ruff-extra-rules runs alongside `ruff format`, and several of its own checks rewrite source layout the same way a formatter would — `excessive-blank-lines` collapses blank runs, `misplaced-comment` relocates trailing comments off bracket-only lines. A region the user has told `ruff format` never to touch should not be silently rewritten, or even flagged, by this tool's own checks either.

This project already has one suppression mechanism: `# pytriage: <code>` (`ignore_pattern_for`, documented in `CONTEXT.md`'s "Inline ignore comment" entry), which every check already applies via one of three shared `_base.py` helpers — `find_ignored_lines`, `ignored_lines_from_tokens`, `find_ignored_lines_and_classify_comments` — each tokenizing `source` itself rather than through `CheckOrchestrator` (a deliberate choice; see ADR-0040).

## Decision

Every check honors `# fmt: off`/`# fmt: on`, `# fmt: skip`, and `# yapf: disable`/`# yapf: enable` with the same standing as this project's own `# pytriage: <code>` comment: a line they cover is suppressed entirely — no violation reported, none fixed. This is implemented once, inside the three shared `_base.py` helpers every check's `check()`/`fix()` already calls (`ignored_lines_from_tokens` and `find_ignored_lines_and_classify_comments` directly; `find_ignored_lines` delegates to the former) via a small stateful `_FormatSuppressionScanner`, fed one token at a time in the same single tokenize pass these functions already run. No check file needs to change, and no new tokenize pass is added.

The scanner is purely `tokenize`-based, with no AST involved:

- A **logical line** starts at the first real code token after a `NEWLINE` (or file start) and ends at the next `NEWLINE`. Tokens inside an open bracket only ever emit `NL`, so a multi-line bracketed expression counts as one logical line throughout.
- `# fmt: off`/`# yapf: disable` and `# fmt: on`/`# yapf: enable` are only recognized as a standalone comment with no logical line currently open — matching the doc's own "statement level" requirement. This also naturally reproduces its "no effect inside an expression" example: a comment inside an open bracket is always seen with a logical line already open (the bracketed expression itself), so the toggle branch is skipped and it's treated as an ordinary comment instead. Either spelling closes whichever one opened it — they are fully interchangeable.
- `# fmt: skip` is only recognized as a comment trailing an already-open logical line; the whole logical line (from its first code token through the closing `NEWLINE`) is suppressed. This naturally covers a decorator, a compound statement's header line, a semicolon-joined run of simple statements, and a multi-line call/collection whose closing line carries the comment — each is its own logical line under this model. Matching ruff's own `SuppressionKind::from_comment` (`ruff_python_trivia/src/comments.rs`), `# fmt: skip` alone is recognized even when interspersed with another pragma on the same trailing comment (e.g. a `noqa` directive sharing the line) — the comment text is split on `#` and each segment checked independently — while `# fmt: off`/`# fmt: on`/`# yapf: disable`/`# yapf: enable` still require the whole comment to be exactly that pragma, same as ruff.
- An unterminated `# fmt: off`/`# yapf: disable` suppresses through end of file, mirroring "no matching close" rather than silently discarding the toggle.

## Considered Options

- **Orchestrator-level filtering of the `Violation` list `CheckOrchestrator` passes around**: rejected. `excessive_blank_lines.fix()` and `misplaced_comment.fix()` both deliberately recompute their own candidate violations from `source` inside `fix()` rather than trusting the caller-supplied `violations` list (see `excessive_blank_lines.fix()`'s own reasoning: "a stale or caller-supplied violations list must never cause an ignored blank run to be collapsed anyway" — the same guarantee that makes a stale `# pytriage:` addition respected mid-run). Filtering only the `Violation` objects the orchestrator sees would not stop these two checks from fixing a suppressed region; the suppression has to live inside the same shared token-scanning helpers every check's own `check()`/`fix()` already calls, which is also where ADR-0040 already keeps every other suppression concern.
- **Report but don't fix, mirroring ruff's own linter/formatter split** (`ruff check` still lints code under `# fmt: off`; only `ruff format` leaves it alone): considered, but rejected in favor of matching this project's one existing suppression mechanism, which suppresses entirely. Confirmed with the user rather than assumed.
- **AST-exact `# fmt: skip` statement-boundary matching**: rejected. Ruff's own formatter ties `# fmt: skip` to the AST's enclosing statement, so a comment trailing a nested list/call element deep inside a still-open multi-line statement has "no effect" (only the outer statement's own last line counts). Reproducing that exactly would mean threading the already-parsed `ast.Module` tree into `find_ignored_lines`/`ignored_lines_from_tokens`/`find_ignored_lines_and_classify_comments` — a new required parameter on every one of the 7 existing call sites across 6 check files — for an edge case ruff's own docs present as a footgun to avoid in the first place. The token-only model instead suppresses the _whole_ enclosing multi-line statement in that case, which is strictly more conservative than ruff (never suppresses less than ruff would; sometimes suppresses a little more). Confirmed with the user as an acceptable, documented scoping choice.
- **A separate `format_suppressed_lines(source)` helper, unioned in at each of the 7 call sites**: rejected. Keeps the three existing helpers' responsibility narrower, but doubles the tokenize cost per check per file — a regression this codebase has repeatedly avoided (see ADR-0040's profiling, and `redundant_assignment`'s `find_ignored_lines_and_classify_comments` itself, whose whole reason for existing is fusing two passes into one).

## Consequences

- Every one of the 7 existing `find_ignored_lines*`/`ignored_lines_from_tokens` call sites gets format suppression for free; no check-specific code changes.
- Widening `ignored_lines` to also mean "protected by the user" (not just "matches this check's own error code") exposed a pre-existing gap in three checks whose fix touches a line other than the one `check()` reports the violation on: `redundant-assignment` (TR5) only checked the _assignment_'s own line against `ignored_lines`, even though its fix rewrites the _use_ site; `validate-function-name` (TR4) only checked the function _definition_'s own line, even though its fix renames every call-site reference too; `meaningless-vars` (TR1) only checked the _assignment_'s own line, even though its fix renames every reference to that name within the enclosing scope. All three are fixed alongside this ADR (`redundant_assignment/__init__.py`'s `check()`; `validate_function_name/autofix.py`'s `apply_fix()`; `meaningless_vars.py`'s `_apply_fixes()`) — every line a fix actually touches is now checked, not just the line the violation is anchored to. `meaningless-vars` refuses per `(scope, old_name)` rather than per occurrence: renaming some references and leaving a suppressed one behind would break the code outright, the same reasoning `validate-function-name` already used for call-site references. Closing this also surfaced (and fixed) a second latent bug in `meaningless-vars`: `fix()` returned `True` unconditionally on a successful `_apply_fixes()` call, even where every rename ended up refused this way and the file was left byte-for-byte unchanged — `_apply_fixes()` now reports whether it actually wrote anything, and `fix()` returns that. All three fixes close the same gap for the pre-existing `# pytriage: TR1`/`# pytriage: TR4`/`# pytriage: TR5` inline ignore comment too, not just the new format-suppression pragmas.
- A `# fmt: skip` trailing a nested sub-expression's own line (rather than the enclosing statement's) suppresses the entire enclosing multi-line statement, not just that one line — a deliberate over-suppression relative to ruff's own AST-exact behavior, covered by a regression test (`test_find_ignored_lines_fmt_skip_on_nested_expression_over_suppresses_whole_statement` in `tests/test_base.py`).
- A `# fmt: off`/`# fmt: on` pragma placed _within_ a decorator chain (between two decorators, or between the last decorator and the `def`/`class` header it decorates) is honored here only for the interval the pragma pair itself marks. Empirically (verified against `ruff 0.16.1` with `ruff format --isolated --diff`, not documented in `docs/formatter.md`), ruff's own formatter does something broader: any suppression pragma anywhere inside a decorator chain makes it leave the _entire_ decorated declaration untouched — every decorator and the `def`/`class` header, not just the marked interval — an implementation detail of how ruff's formatter groups a decorator list with the node it decorates, not a documented per-statement rule. Unlike the `# fmt: skip` nested-expression case above (where this scanner suppresses _more_ than ruff), this is the opposite direction: a decorator or header line outside the pragma pair's own interval is fair game to this tool's own checks even though ruff itself would leave it untouched too. Reproducing ruff's actual scope here would need the scanner to buffer or look ahead across an entire decorator chain before deciding whether a pragma inside it takes effect, for a case obscure enough that it isn't in ruff's own docs — judged out of proportion with the value, and accepted as a known, tested limitation (`test_find_ignored_lines_fmt_off_between_decorators_only_covers_the_marked_interval` in `tests/test_base.py`) rather than a silent gap.
- `ignored_lines_from_tokens`'s and `find_ignored_lines_and_classify_comments`'s own responsibility widens from "lines with a comment matching a caller-supplied pattern" to also include format-suppressed lines unconditionally (not gated by any pattern argument) — documented in both functions' own docstrings so this isn't silently conflated with the `# pytriage:`-specific behavior `CONTEXT.md`'s glossary describes.
- Should a future check need AST-exact `# fmt: skip` fidelity, or should the token-only over-suppression prove to hide real violations often enough to matter in practice, revisit the rejected AST-threading option above then, with real evidence rather than the a-priori concern here.
